# ルールベースによる席周辺セグメント抽出とテーブル領域推定

## 1. 目的

この実装の目的は、Data001 / Data002 のうち、テーブルA・テーブルCへ向かう軌跡から、テーブル周辺の位置を推定することです。

本研究では、事前に店舗地図やテーブル位置が分からない前提を置きます。そのため、分析に使う情報は基本的に以下です。

- 歩行軌跡の座標
- 各ステップの時刻
- 各ステップの進行方向
- 各ステップの歩行速度
- 入口を原点とする仮定

図中に表示しているテーブル枠は、推定結果を確認するための背景表示です。分類やクラスタリングには使いません。

## 2. 全体の流れ

処理は大きく4段階です。

1. 軌跡を読み込む
2. 1本の軌跡を複数のセグメントに分割する
3. 各セグメントを `corridor` / `seat_area` に分類する
4. `seat_area` セグメントの代表点をクラスタリングし、テーブル周辺の代表点を求める

ここでいうセグメントとは、1本の軌跡をいくつかに切った部分軌跡です。

例えば、1本の軌跡は次のように分けられます。

```text
入口付近の通路セグメント
→ 通路上の曲がりセグメント
→ テーブル付近で減速するセグメント
→ 席の奥側へ回り込むセグメント
```

このうち、テーブル位置推定に使いたいのは `seat_area` セグメントです。

## 3. ステップ単位の特徴量

まず、軌跡の各ステップに対して特徴量を計算します。

### 3.1 歩行速度

各ステップの速度は、歩幅と時間差から求めます。

```text
speed_mps = step_length_m / dt_s
```

現在のPDR設定では、基本の歩幅は以下です。

```text
step_length_m = 0.60m
```

### 3.2 直前4ステップの平均速度

現在ステップが速いか遅いかを判断するため、直前4ステップの平均速度を使います。

```text
previous_speed_mps = 直前4ステップの平均速度
```

### 3.3 減速点

現在ステップの速度が、直前4ステップ平均速度より20%以上低下した場合、そのステップを減速点とします。

```text
speed_drop_ratio =
(直前4ステップ平均速度 - 現在速度) / 直前4ステップ平均速度
```

```text
speed_drop_ratio >= 0.20
```

なら減速点です。

## 4. セグメント分割

セグメント分割では、軌跡を「動きの変化が起きた場所」で切ります。

現在の分割条件は以下です。

```text
2ステップ累積の進行方向変化 >= 20度
または
速度変化率 >= 20%
```

### 4.1 2ステップ累積の進行方向変化

各ステップでは、直前ステップから現在ステップへの進行方向変化を計算しています。

```text
heading_delta[i] = | heading[i] - heading[i-1] |
```

ただし、1ステップだけを見ると、円弧のように少しずつ曲がる動作を拾いにくいです。

そのため、現在は直近2ステップ分を足しています。

```text
heading_delta[i-1] + heading_delta[i] >= 20度
```

この条件を満たす場合、そこでセグメントを分割します。

### 4.2 速度変化

速度が急に変わった場合も、動作が変わった可能性があります。

そのため、速度変化率が20%以上の場合も分割候補にします。

```text
speed_change_ratio >= 0.20
```

### 4.3 細かすぎる分割の抑制

分割が細かくなりすぎないように、以下を設定しています。

```text
min_segment_steps = 2
min_boundary_gap_steps = 2
```

つまり、1ステップだけの短すぎるセグメントは避け、最低2ステップ程度のまとまりを作ります。

## 5. セグメント単位の特徴量

分割された各セグメントについて、次の特徴量を計算します。

### 5.1 slowdown_ratio

`slowdown_ratio` は、セグメント内に減速点がどれくらい含まれるかを表します。

```text
slowdown_ratio =
セグメント内の減速点数 / セグメント内の全ステップ数
```

例えば、2ステップのセグメントで1ステップが減速点なら、

```text
slowdown_ratio = 1 / 2 = 0.5
```

です。

現在は、

```text
slowdown_ratio >= 0.10
```

を減速セグメントの条件にしています。

短いセグメントが多いため、実質的には「セグメント内に少なくとも1つ減速点があるか」に近い判定です。

### 5.2 heading_change_deg

`heading_change_deg` は、セグメント内で進行方向が合計どれだけ変わったかを表します。

```text
heading_change_deg =
セグメント内の heading_delta の合計
```

例えば、セグメント内で進行方向変化が

```text
10度, 12度, 15度
```

なら、

```text
heading_change_deg = 37度
```

です。

この値は、席の奥側へ回り込むような曲がり動作を拾うために使います。

### 5.3 path_length_m

`path_length_m` は、そのセグメント内で実際に歩いた距離です。

```text
path_length_m =
セグメント内の隣接点間距離の合計
```

現在の歩幅設定は約0.60mなので、

```text
path_length_m <= 1.2m
```

は、おおよそ2歩程度の短い局所的な動きを意味します。

## 6. seat_area / corridor 分類ルール

各セグメントを以下の2種類に分類します。

```text
corridor: 通路を歩いているセグメント
seat_area: テーブル・席周辺のセグメント
```

現在の30度版ルールでは、以下のどちらかを満たすセグメントを `seat_area` とします。

```text
ルール1: 短い減速セグメント
ルール2: 短い回り込みセグメント
```

### 6.1 ルール1: 短い減速セグメント

席周辺では、座る・止まる・迷うなどの動作により速度が落ちやすいです。

そのため、減速があり、かつ長すぎないセグメントを `seat_area` とします。

```text
slowdown_ratio >= 0.10
AND
path_length_m <= 1.2
```

長さ条件を入れる理由は、通路上の長いセグメントの途中で1点だけ減速した場合に、セグメント全体を席周辺として誤分類しないためです。

### 6.2 ルール2: 短い回り込みセグメント

テーブルの奥側の席に座ろうとすると、テーブル付近で短い距離の中で向きを変える動きが出ます。

そのため、次の条件を満たすセグメントも `seat_area` とします。

```text
heading_change_deg >= 30
AND
減速セグメントの近くにある
AND
path_length_m <= 1.2
```

### 6.3 減速セグメントの近くとは

「減速セグメントの近く」は、以下のどちらかを満たす場合です。

```text
同じ軌跡で前後1セグメント以内
または
代表点同士の距離が0.8m以内
```

この条件を入れる理由は、通路上でも曲がることがあるためです。

単に曲がっただけでは `seat_area` とせず、減速が起きている場所の近くで曲がっている場合に、席周辺の回り込み動作とみなします。

### 6.4 最終的な分類式

現在の30度版ルールは、まとめると以下です。

```text
seat_area =
(
  slowdown_ratio >= 0.10
  AND
  path_length_m <= 1.2
)
OR
(
  heading_change_deg >= 30
  AND
  near_slowdown_segment == True
  AND
  path_length_m <= 1.2
)
```

それ以外は `corridor` とします。

## 7. 現在の30度版の結果

Data001 / Data002 のテーブルA・C軌跡に適用した結果は以下です。

```text
seat_area: 36
corridor: 45
```

ラベル別では以下です。

```text
A seat_area: 16
C seat_area: 20
```

内訳は以下です。

```text
A: 減速 10, 回り込み 6
C: 減速 9, 回り込み 11
```

クラスタリング後の推定代表点は以下です。

```text
A 推定代表点: x = -1.048, y = 4.773
C 推定代表点: x = -5.289, y = 5.554
```

## 8. なぜ30度にしたのか

45度では、明らかに回り込みに見えるセグメントの一部が `corridor` として残ることがありました。

一方で、30度に下げると、席周辺の曲がりをより拾いやすくなります。

ただし、30度は45度より緩いため、通路上の曲がりを拾う危険も少し増えます。そこで、以下の抑制条件を組み合わせています。

```text
減速セグメントの近くにある
AND
path_length_m <= 1.2
```

この2条件により、単なる通路カーブではなく、短い局所的な回り込みを拾うようにしています。

## 9. テーブル代表点の求め方

`seat_area` と判定されたセグメントから代表点を1つずつ作ります。

代表点は、セグメント内の特徴点の平均座標です。

特徴点は以下を優先します。

```text
減速点
または
低速点
```

該当する点がない場合は、そのセグメントの末尾点を使います。

その後、AとCを別々にDBSCANでクラスタリングします。

現在の設定は以下です。

```text
DBSCAN eps = 1.2m
min_samples = 2
```

クラスタリング後、最大クラスタの重心をテーブル周辺の推定代表点とします。

## 10. 今後の領域推定に向けた展望

現在は、テーブル周辺を「一点の代表点」として推定しています。

今後は、この代表点をもとに、テーブルや席周辺の「領域」を推定する方向へ拡張できます。

### 10.1 代表点から領域へ

まずは、`seat_area` セグメント代表点のクラスタを使って、代表点だけでなく範囲を求めます。

候補は以下です。

- クラスタの平均と分散
- 信頼楕円
- 凸包
- 外れ値除去後の包絡領域
- グリッド密度による領域推定

### 10.2 信頼楕円による表現

一番扱いやすいのは、クラスタ点群の平均と分散から楕円を作る方法です。

```text
クラスタ中心 = テーブル代表点
楕円の大きさ = 点群のばらつき
```

これにより、「このあたりがテーブル周辺である」という領域を見やすく表示できます。

### 10.3 密度ベースの領域推定

点群をグリッドに投影し、点が多い場所をテーブル周辺領域とする方法もあります。

この方法では、形が円や楕円でない場合にも対応しやすくなります。

流れは以下です。

1. 空間を小さなグリッドに分割する
2. 各グリッドに含まれる seat_area 点の数を数える
3. 密度が高いグリッドを抽出する
4. 隣接する高密度グリッドをまとめて領域にする

### 10.4 セグメント線分を使う方法

現在はセグメント代表点を主に使っています。

しかし、席周辺セグメントは点ではなく線分として存在します。

そのため今後は、以下のように線分情報も使えます。

- seat_area セグメント上の全ステップ点を使う
- セグメント線分の周囲にバッファを作る
- バッファが重なる場所をテーブル周辺領域とする

これにより、代表点だけではなく、実際に人が動いた範囲を反映した領域推定ができます。

### 10.5 時系列的な更新

本来のユースケースでは、軌跡はリアルタイムに増えていく可能性があります。

その場合、以下のような逐次更新が必要です。

- 新しい軌跡が来たらセグメント分割する
- seat_area セグメントを追加する
- クラスタ代表点と領域を更新する
- 古い外れ値やノイズを除く

これにより、地図なしの状態から徐々にテーブル周辺領域を推定できます。

## 11. 今後確認すべき点

今後の検証では、以下を確認するとよいです。

- 30度条件で通路カーブを拾いすぎていないか
- `path_length_m <= 1.2` が他データでも妥当か
- Data001 / Data002 以外でも同じルールが使えるか
- A/C以外のテーブルにも適用できるか
- 代表点だけでなく領域として表示したときに、テーブル周辺を自然に表現できるか
- 地図情報なしでも、複数軌跡から安定して領域が収束するか
